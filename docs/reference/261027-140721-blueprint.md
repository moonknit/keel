## 파트별 핵심 결정

### 01 core-loop
- `Model` `Tool` `Approver` `Store` trait만 core에 둔다. core는 SQLite·HTTP·터미널을 모른다. 근거: [pi](https://github.com/earendil-works/pi)가 하네스를 `pi-agent-core` 밖으로 뺀 구조.
- tool call은 한 턴 안에서 직렬. 근거: 단순성. 읽기 병렬은 나중.
- 훅 이름 `before_tool` `after_tool` `prepare_next_turn` `should_stop`. 근거: pi 훅.
- `max_turns` 50, 취소는 `CancellationToken`. 결과 없는 tool call에는 tool result를 합성한다.

### 02 model-openai
- `async-openai` 대신 `reqwest` + SSE + `serde_json::Value` 그대로 전달. 근거: typed SDK가 모르는 필드를 왕복에서 잃으면 reasoning 재전송이 깨진다([OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning)).
- hosted `web_search`는 로컬 레지스트리가 아니라 요청에 붙인다. `user_location` 기본 KR. 근거: 생략 시 미국 기준([web search](https://developers.openai.com/api/docs/guides/tools-web-search)).
- 429/5xx 지수 백오프 3회, context 초과는 chat을 더 빼고 1회 재시도.

### 03 session-store
- 단일 DB + `session.cwd`로 워크스페이스 구분. 근거: [goose](https://github.com/aaif-goose/goose) SQLite 세션, 목록 쿼리.
- `message.body`(정규화) + `raw`(원본) 이중 저장. 근거: 화면·검색과 무손실 재전송을 둘 다.
- 열 때 복구: `running` → `interrupted`, 짝 없는 tool call에 결과 합성. 근거: [Claude Code sessions](https://code.claude.com/docs/en/sessions)는 끊긴 도구를 재실행하지 않는다.
- `lock_pid`로 같은 session 동시 열기 차단. 근거: Claude Code 문서의 두 터미널 섞임 문제.
- context 축소는 오래된 chat 통째 생략 + 일회성 안내. 진행 중 chat은 자르지 않는다.
- rusqlite는 전용 스레드. 근거: 동기 API를 async 루프에서 막지 않게.

### 04 tools
- `bash`는 호출마다 새 프로세스, 프로세스 그룹 kill, 타임아웃 120초(최대 600초), 출력 30,000자에서 앞뒤 보존. 근거: [mini-swe-agent](https://github.com/SWE-agent/mini-swe-agent) 독립 subprocess.
- `edit`는 old/new 정확 일치만. 근거: pi. patch는 모델 실수 시 복구가 어렵다.
- 승인 once / always / deny. 위험 패턴은 always여도 다시 묻는다. 휴리스틱이고 보안 경계가 아님을 명시.
- `--allow-edits`만 두고 `--yolo`는 없다.
- 경로는 canonicalize 후 cwd·스킬 루트 안인지 검사(심링크 탈출 방지).

### 05 mcp
- `rmcp`, stdio + streamable HTTP. 연결 10초 타임아웃, 서버 실패는 그 서버 도구만 에러.
- 이름 `<server>__<tool>` 고정. 근거: function 이름에 점이 허용되는지 불명.
- MCP 도구는 External 클래스로 항상 승인 대상.

### 06 skills
- 탐색 `.agents/skills/`(cwd → git 루트) → `~/.agents/skills/` → `.claude/skills/` 호환. 먼저 찾은 이름이 이긴다.
- 카탈로그(name + description)만 시스템 프롬프트, 4,000자 상한. 본문은 `skill` 도구 또는 `/skill:name`. 근거: [Agent Skills](https://agentskills.io/specification) progressive disclosure, pi.
- 스킬 루트는 session 범위 읽기 허용. resume 시 skill 메시지에서 복원.
- `AGENTS.md` 지원, 16,000자 상한, `CLAUDE.md`는 읽지 않음. 근거: [tiny-agents](https://huggingface.co/blog/tiny-agents), pi.

### 07 cli
- clap 명령 + rustyline REPL. tool은 한 줄 요약, `/last`로 전체.
- Ctrl-C는 chat 취소, 두 번 또는 Ctrl-D는 종료.
- `keel -p` 종료 코드 0 / 1 / 2 / 130. 근거: pi print 모드, 종단 테스트.

### 08 platform
- crate 7개(core, store, openai, tools, mcp, skills, cli). 근거: core 의존 금지를 컴파일러로 강제.
- 로그는 `~/.keel/logs/`에만. 라이브러리 `thiserror`, cli `anyhow`.
- 테스트는 `ScriptedModel` + `MemoryStore`. 실제 API는 `KEEL_LIVE=1`.

## 기각한 대안

| 대안 | 기각 이유 |
|---|---|
| Rig·llm-agent-runtime에 루프 위임 | 루프가 제품의 커널이다 |
| Chat Completions | hosted 검색을 같은 요청에 못 섞는다 |
| `previous_response_id`(서버 상태) | 로컬 DB가 정본이어야 resume·생략이 된다 |
| OpenAI hosted shell / code_interpreter | 워크스페이스를 원격에 올리지 않는다 |
| 세션마다 JSONL | 목록·검색 쿼리가 약하다 |
| 커널 안 Python 인터프리터(smolagents) | bash로 충분하고 무겁다 |
| 상태 있는 셸 | 샌드박스 교체가 어려워진다(RV-010에서 재검토) |
| 스킬 전용 `read_skill_file` | `read` + 허용 루트로 충분 |
| `server.tool` 이름 | function 이름 규칙 위반 위험 |
| v1 요약 compaction | 모델 호출·실패 처리 추가. 생략으로 먼저 본다 |
| v1 Steer | REPL에서 실행 중 입력 비용 |
| `--yolo` | 위험 패턴 확인을 우회한다 |
