1. 이 문서를 읽는 법

에디터에서 crates/keel-cli/src/main.rs를 열어 두고, 아래 코드를 원본과 대조하며 읽는 편이 좋습니다. 예시는 설명을 위해 줄인 곳이 있습니다. 빠진 줄이 있으면 원본이 정본입니다.

Rust는 “값이 누구 것인가”를 컴파일러가 검사합니다. 그래서 clone(), &, .to_string()이 다른 언어보다 자주 보입니다. 이상해 보여도 대부분 “빌려 쓰기 / 복사해서 주기 / 소유권 넘기기” 중 하나입니다.

2. 파일이 나뉜 이유

keel-cli 바이너리의 입구는 main.rs입니다. 같은 폴더의 다른 .rs는 mod 이름;으로 붙는 모듈입니다. 

// crates/keel-cli/src/main.rs  위쪽
mod config;   // → config.rs
mod last;     // → last.rs
mod logging;  // → logging.rs
mod slash;    // → slash.rs
파일읽는 포인트
main.rs 플래그 파싱, 기동, REPL 루프. 가장 먼저 볼 파일.
slash.rs /new, /resume 문자열을 enum으로 바꾸고 session을 갈아탑니다.
last.rs 저장된 대화에서 마지막 도구 출력을 찾습니다. 이터레이터 연습에 좋습니다.
config.rs / logging.rs 설정·로그. REPL 한 줄을 이해하는 데 필수는 아닙니다.
keel-core/src/agent.rs 엔터 이후의 본체. CLI가 만든 Agent가 여기서 돕니다.
keel-core/src/traits.rs Model, Tool, Store처럼 “역할만 정한 인터페이스”.
keel-core/src/types.rs Event, Item, RunStatus 같은 데이터 모양.

mod slash;를 쓰면 같은 crate 안에서는 slash::parse_session_switch(...)처럼 호출합니다. pub fn만 crate 밖이나 다른 모듈에서 부를 수 있습니다. fn만 있으면 그 파일(모듈) 전용입니다.

3. 코드를 막히게 하는 Rust 문법

여기 있는 것만 알면 이 프로젝트의 CLI 코드는 대부분 읽힙니다. 문법 책 순서가 아니라, 이 저장소에서 자주 나오는 순서입니다.

소유권, 빌림, 복사

코드읽기
s 이 값을 내가 가진다. 다른 함수에 s를 넘기면 내 손에서 떠납니다(move).
&s 읽기만 빌려 준다. 함수가 끝나도 s는 그대로 있다.
&mut s 고칠 수 있게 빌려 준다. 같은 값을 동시에 두 곳에서 고칠 수는 없다.
s.clone() 같은 내용의 새 값을 만든다. 문자열·구조체를 두 곳에서 갖고 싶을 때.
s.to_string() / s.into() &str(문자열 조각)을 소유하는 String으로 만든다. 
// 이 프로젝트에서 자주 보는 세 가지
fn pick_session(cwd: &str, ...) // cwd는 빌려 읽기만
let session_id = session_id.to_string(); // &str → 내가 가진 String
store.rename(&session_id, name) // String을 넘기지 않고 내용만 빌려 줌
&str은 “어딘가에 있는 글자의 창”이고, String은 “내가 들고 있는 글자 상자”입니다. 함수 인자로 읽기만 하면 &str, 저장하거나 나중에 쓰려면 String으로 복사합니다.

Option과 Result, 그리고 ?

Rust에는 null이 없습니다. “있을 수도 없다”는 Option<T>, “실패할 수도 있다”는 Result<T, E>입니다. 

enum Option<T> { Some(T), None }
enum Result<T, E> { Ok(T), Err(E) }
코드읽기
if let Some(x) = ... 있으면 x로 풀고, 없으면 이 분기를 건너뛴다.
let x = y?; y가 Ok/Some이면 안을 꺼낸다. 아니면 지금 함수를 그 실패값으로 끝낸다.
.unwrap() / .expect("...") 없다고 치고 꺼낸다. 없으면 패닉. 테스트나 “여기는 반드시 있다”에만.
.ok() Result를 Option으로. 에러 내용은 버린다.
.map_err(into) 에러 타입만 바꾼 뒤 그대로 ?에 넘긴다. 
// main.rs  — Result를 받는 함수. 실패하면 호출한 쪽으로 올라간다.
async fn run() -> Result<()> {
    let cwd = std::env::current_dir()?;   // 실패면 run()이 Err로 끝
    ...
    Ok(())                                // 성공. ()는 “값 없음”
}

Result<()>의 ()는 빈 튜플입니다. “일만 하고 돌려줄 값은 없다”는 뜻입니다. keel-cli는 anyhow::Result를 씁니다. 여러 종류의 에러를 한 덩어리로 다루는 편의 타입입니다. keel-core는 자기 KeelError를 씁니다. CLI는 into()로 둘을 잇습니다.

match와 패턴

switch보다 강합니다. 모든 경우를 써야 하고, 안의 값까지 꺼내서 이름을 붙일 수 있습니다. 

match line.trim() {
    "a" | "always" => Decision::Always,  // 둘 중 하나
    "n" | "no"     => Decision::Deny,
    _              => Decision::Once,    // 그 외 전부. _ 는 “이름 안 붙임”
}

// enum 안의 필드를 꺼내는 패턴
if let Event::TextDelta(s) = ev {
    print!("{s}");   // ev가 TextDelta일 때만 s를 얻음
}

struct, enum, impl

struct Agent {            // 여러 칸을 가진 상자
    pub model: ...,       // pub = 다른 모듈에서도 이 칸을 볼 수 있음
    max_turns: u32,
}

enum RunStatus { Done, Interrupted, Error, Limit }  // 넷 중 하나

impl Agent {              // Agent에 함수를 붙임
    pub async fn run(&self, ...) { ... }  // &self = 상자를 빌려 읽음
}

&self는 파이썬의 self와 비슷하되, 빌려 씁니다. self만 있으면 호출 뒤에 그 값은 함수 안으로 들어갑니다. 이 코드의 run은 같은 Agent로 여러 줄을 처리하므로 항상 &self입니다.

trait과 dyn, Arc

trait은 “이 함수들을 가진 타입이면 된다”는 역할입니다. dyn Model은 “Model 역할을 하는 어떤 타입이든”입니다. 실제로는 OpenAI일 수도, 테스트용 가짜일 수도 있습니다. 

let model: Arc<dyn Model> = if 테스트 {
    Arc::new(ScriptedModel::...)
} else {
    Arc::new(OpenAiModel::from_env()?)
};
Arc<T>
Atomic Reference Counted. 같은 값을 여러 곳이 나눠 갖는 손잡이입니다. 복제(clone)해도 내용이 복사되지 않고 카운트만 올라갑니다. REPL과 에이전트가 같은 저장소를 볼 때 씁니다.
Box<T>
힙에 올려 둔 한 개의 값. PolicyApprover 안의 inner: Box<dyn Approver>가 이런 경우입니다. 안쪽 승인자가 키보드일 수도, 무조건 거부일 수도 있어서 크기를 컴파일 때 고정할 수 없습니다.
Send + Sync
다른 스레드/태스크로 보내도 되는 타입(Send), 동시에 빌려 읽어도 되는 타입(Sync). async 작업에 넘기려면 이 두 표시가 필요합니다.

async / await / tokio::spawn

네트워크·키보드처럼 기다리는 일이 있으면 함수에 async를 붙입니다. 호출하는 쪽은 .await로 “여기서 결과가 올 때까지 이 작업은 양보”합니다. 프로그램 전체가 멈추는 것은 아닙니다. 런타임이 다른 작업을 돌립니다. 

async fn repl(...) -> Result<()> {
    let status = agent.run(...).await?;   // 모델이 답할 때까지 이 줄에서 양보
}

// 동시에 다른 일을 시키고 싶을 때
let printer = tokio::spawn(async move {
    while let Some(ev) = rx.recv().await { ... }
});
async move { ... }의 move는 클로저가 바깥 변수를 가져간다는 뜻입니다. 프린터 작업이 rx를 가져가므로, 원래 함수는 더 이상 rx를 쓰면 안 됩니다. 그래서 let (tx, mut rx)로 만든 뒤 tx는 agent.run에, rx는 프린터에 나눕니다.

매크로와 속성

보이는 것역할
println!(...)매크로. 함수처럼 보이지만 !가 붙습니다. 포맷 문자열을 컴파일 때 검사합니다.
format!("{} {}", a, b)출력 대신 String을 만듭니다.
#[tokio::main]속성. async fn main을 런타임이 돌릴 수 있게 감쌉니다.
#[derive(Parser)]구조체에서 clap이 플래그 파서를 자동 생성합니다.
#[async_trait]trait 안의 async fn을 지금 Rust가 소화하는 형태로 바꿔 줍니다.
vec![a, b]Vec(가변 배열)을 만드는 매크로.
matches!(x, Pattern)패턴이면 true. if let을 한 줄로 줄인 형태.

4. main.rs 맨 위: use, mod, clap

use — 이름을 짧게 쓰기

// crates/keel-cli/src/main.rs
use anyhow::Result;
use clap::{Parser, Subcommand};
use keel_core::agent::Agent;
use std::sync::Arc;
use tokio::sync::mpsc;

use 경로::이름;은 “이 파일을 읽는 동안 짧은 이름만 쓰겠다”입니다. keel_core::agent::Agent를 매번 쓰지 않고 Agent로 부릅니다. crate 이름은 Cargo.toml의 keel-core가 코드에서는 밑줄 keel_core가 됩니다.

플래그를 구조체로 받기

#[derive(Parser)]
#[command(name = "keel")]
struct Cli {
    #[arg(long)]
    new: bool,                          // --new  → true/false
    #[arg(long)]
    resume: Option<Option<String>>,    // 아래 설명
    #[arg(short = 'p', long)]
    prompt: Option<String>,             // -p "..." 가 없으면 None
    #[arg(long)]
    allow_edits: bool,
    #[arg(long, default_value_t = false)]
    r#continue: bool,                   // continue는 예약어라 r# 접두사
    #[command(subcommand)]
    cmd: Option<Cmd>,                   // session list 같은 하위 명령
}

Option<Option<String>>이 낯설면 clap의 관용입니다.

입력cli.resume
플래그 없음None
--resumeSome(None) — 켰지만 id는 안 줌
--resume abcSome(Some("abc"))

그래서 나중에 cli.resume.clone().flatten()을 씁니다. flatten은 Option<Option<T>>을 Option<T>로 납작하게 만듭니다. 두 번째 None(플래그만 있음)도 그냥 “id 없음”이 됩니다. clone()은 parse가 만든 Cli를 나중에 또 쓰려고 소유권을 빼앗지 않기 위함입니다.

하위 명령은 중첩 enum입니다. keel session list --all은 Cmd::Session { action: SessionCmd::List { all: true } }가 됩니다. 

#[derive(Subcommand)]
enum Cmd {
    Session {
        #[command(subcommand)]
        action: SessionCmd,
    },
}

#[derive(Subcommand)]
enum SessionCmd {
    List { all: bool },
    Show { id: String },
    Rm { id: String },
}

5. main과 run

#[tokio::main]
async fn main() {
    let _ = dotenvy::dotenv();          // .env를 환경 변수로. 실패해도 무시
    if let Err(e) = run().await {
        eprintln!("{e}");               // stderr로 에러 출력
        std::process::exit(1);
    }
}

let _ = ...는 “반환값을 쓰지는 않겠다”입니다. dotenv()는 파일이 없으면 에러를 돌리지만, 키가 이미 환경에 있으면 파일 없이도 동작하므로 여기선 버립니다.

main은 Result를 돌려주지 않습니다. 실패를 프로세스 종료 코드로 바꿉니다. 실제 일은 run()에 모아 두어 ?를 편하게 쓰게 합니다. 

async fn run() -> Result<()> {
    let cli = Cli::parse();                       // argv → Cli
    let home = keel_home();
    std::fs::create_dir_all(&home).ok();          // 실패해도 계속
    let _logging = logging::init(&home)?;         // 가드가 살아 있는 동안 로그
    let db = SqliteStore::open(&home.join("keel.db"))?;
    let cwd = std::env::current_dir()?;
    let cwd_s = cwd.to_string_lossy().into_owned();
    let mut cfg = config::load(&home, &cwd)?;
    ...
}
home.join("keel.db")
PathBuf에 파일 이름을 붙입니다. &home을 넘기는 이유는 join이 &Path를 받기 때문입니다. home은 그대로 둡니다.
to_string_lossy().into_owned()
경로는 OS 문자열이라 UTF-8이 아닐 수 있습니다. to_string_lossy는 깨진 글자를 �로 바꾼 Cow<str>(빌려 오거나, 필요하면 소유)를 줍니다. into_owned가 그걸 진짜 String으로 만듭니다. 이후 DB·모델에 넘기는 값은 모두 &str로 빌려 씁니다.
let mut cfg
기본은 불변입니다. 신뢰 확인 뒤에 cfg.needs_confirm = false로 고치므로 mut가 필요합니다.
let _logging = ...
LogGuard를 변수에 붙잡아 둡니다. 밑줄은 “이름은 안 쓰지만 값은 살려 둔다”입니다. run이 끝나는 순간 Drop이 호출되어 로그를 flush합니다. let _ = logging::init(...)?로 쓰면 그 줄에서 바로 버려져 로거가 먼저 닫힙니다.

홈 디렉터리

fn keel_home() -> PathBuf {
    if let Ok(h) = std::env::var("KEEL_HOME") {
        return PathBuf::from(h);        // 환경 변수가 있으면 즉시 반환
    }
    dirs_home().join(".keel")           // 마지막 식이 반환값. return 생략
}

Rust 함수의 마지막 식에 세미콜론이 없으면 그 값이 반환입니다. return은 중간에 나갈 때 더 자주 씁니다. std::env::var은 Result<String, VarError>라서 if let Ok(h)로 성공만 받습니다.

하위 명령이면 여기서 끝

match cli.cmd {
    Some(Cmd::Session { action }) => {
        return session_cmd(&db, &cwd_s, action).await;
    }
    None => {}                          // REPL/print로 계속
}

Cmd::Session { action }은 “이 갈래이고, 안의 action을 꺼내 쓰겠다”는 패턴입니다. return ...await이므로 session list를 치면 REPL에 들어가지 않습니다.

print 모드와 REPL 분기

let print = cli.prompt.clone();
let allow_edits = cli.allow_edits;
if let Some(prompt) = print {
    let code = run_print(&db, &session.meta.id, &cwd_s, &prompt, allow_edits, &cfg).await?;
    std::process::exit(code);
}
repl(&db, &session.meta.id, &cwd, allow_edits, &cfg, &model_name).await

cli.prompt는 Option<String>입니다. clone()하는 이유: 아래에서 cli를 더 쓸 수도 있고, if let Some(prompt)가 String을 꺼내 가면 원본 cli.prompt는 빈 자리가 됩니다. 지금은 복제본을 소비합니다.

run_print는 i32 종료 코드를 돌립니다. repl은 Result<()>라서 함수의 마지막 식으로 그대로 올라갑니다. 둘의 반환 타입이 다릅니다. 그래서 print 쪽은 exit로 프로세스를 끝냅니다.

6. session을 고르는 코드

async fn pick_session(
    db: &SqliteStore,                   // 빌려 씀. 함수가 저장소를 소유하지 않음
    cwd: &str,
    model: &str,
    cli: &Cli,
) -> Result<keel_core::WorkingSession> {
    if cli.new {
        return db.create_session(cwd, model).await.map_err(into);
    }
    slash::resume_session(db, cwd, model, cli.resume.clone().flatten().as_deref())
        .await
        .map_err(into)
}

한 줄에 문법이 여러 개 겹칩니다. 안에서부터 읽습니다.

  1. cli.resume.clone() — Option<Option<String>> 복사.
  2. .flatten() — Option<String>.
  3. .as_deref() — Option<&str>. String을 빌려 &str로 봅니다. resume_session이 id: Option<&str>를 받기 때문입니다.
  4. .await — 비동기 함수의 결과(keel_core::Result<...>).
  5. .map_err(into) — 에러만 anyhow::Error로 변환. into는 아래 작은 함수입니다.
fn into(e: keel_core::KeelError) -> anyhow::Error {
    anyhow::anyhow!(e.to_string())
}

.map_err(into)는 .map_err(|e| into(e))와 같습니다. 함수 이름만 넘기면 클로저를 생략할 수 있습니다.

--new가 아니면 전부 resume_session으로 갑니다. id가 있으면 그걸 열고, 없으면 이 cwd의 최근 session, 그것도 없으면 새로 만듭니다. 본문은 slash.rs에 있습니다.

7. Agent를 조립하는 코드

build_agent는 화면이 아니라 상자만 만듭니다. 반환 타입은 Result<Agent>입니다. 

async fn build_agent(
    store: Arc<dyn Store>,              // 이미 손잡이로 받음
    cwd: &std::path::Path,
    print: bool,
    allow_edits: bool,

    let skills = discover(cwd);
    let mut tools = coding_tools();     // Vec<Arc<dyn Tool>>
    tools.push(Arc::new(SkillTool { skills: skills.clone() }));
    tools.extend(attach_mcp_tools(cfg).await);
    ...
}
let mut tools

struct StdinApprover;

#[async_trait]
impl Approver for StdinApprover {
    async fn approve(&self, req: &ApprovalRequest) -> Decision {
        eprintln!(
            "  allow {} {}? [y]es [a]lways [n]o",
            req.name, req.args_summary
        );
        let mut line = String::new();
        let _ = std::io::stdin().read_line(&mut line);

}

10. slash.rs: 문자열을 enum으로

파일 맨 위 //!는 crate/모듈 문서 주석입니다. //는 일반 주석입니다. 

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum SessionSwitch {
    New,
    Resume(Option<String>),             // 갈래가 값을 가짐
}

pub fn parse_session_switch(line: &str) -> Option<SessionSwitch> {
    if line == "/new" {
        return Some(SessionSwitch::New);
    }
    if line == "/resume" {
        return Some(SessionSwitch::Resume(None));
    }
    let rest = line.strip_prefix("/resume ")?;
    let id = rest.split_whitespace().next().unwrap_or("");
    if id.is_empty() {
        Some(SessionSwitch::Resume(None))
    } else {
        Some(SessionSwitch::Resume(Some(id.to_string())))
    }
}

여기 ?는 Result가 아니라 Option에 붙었습니다. strip_prefix가 None이면 함수 전체가 None으로 끝납니다. “/resume 로 시작하지 않으면 이 함수의 일이 아니다” 를 한 글자로 쓴 것입니다.

/new extra는 첫 분기에도, prefix에도 안 걸려 None입니다. 그러면 REPL은 일반 프롬프트로 모델에 보냅니다.

실패하면 이전 session을 다시 잠그기

pub async fn apply_session_switch(...) -> Result<String> {
    store.close(current_id).await?;
    let opened = match switch {
        SessionSwitch::New => store.create_session(cwd, model).await,
        SessionSwitch::Resume(id) => {
            resume_session(store, cwd, model, id.as_deref()).await
        }
    };
    match opened {
        Ok(ws) => Ok(ws.meta.id),
        Err(e) => {
            if store.open_session(current_id).await.is_err() {
                return Err(KeelError::Msg(format!(
                    "{e}; also failed to restore session {current_id}"
                )));
            }
            Err(e)
        }
    }
}

id.as_deref() — Option<String>을 Option<&str>로. Resume(id)에서 id는 패턴으로 꺼낸 값입니다.

새 session을 열기 전에 현재 것을 close합니다. 열기가 실패하면 예전 id를 다시 open_session합니다. .is_err()는 내용이 아니라 실패 여부만 봅니다. 복구까지 실패하면 두 에러를 한 문자열로 합칩니다. 복구가 되면 원래 에러 e만 다시 올립니다. 호출한 REPL은 eprintln하고, session_id는 바꾸지 않습니다.

resume_session 본체:

    return store.open_session(id).await;
}
let list = store.list_sessions(Some(cwd), false).await?;

Some(cwd)는 Option<&str>를 만듭니다. “이 cwd만 보라”는 뜻입니다. None이면 전체입니다. into_iter().next()는 첫 원소만 꺼내고 벡터는 소비합니다. 목록이 비면 None → 새로 만듭니다.

11. last.rs: 이터레이터 체인

한 함수가 이터레이터를 길게 이어 붙인 예입니다. 왼쪽에서 오른쪽으로, “다음 단계의 흐름”으로 읽습니다. 

pub fn last_tool_output(session: &WorkingSession) -> Option<&str> {
    session
        .chats
        .iter()                         // 각 chat을 &Chat 로
        .rev()                          // 최신 chat부터
        .flat_map(|c| c.items.iter().rev())  // chat 안의 item을 최신부터 펼침
        .find_map(|item| match &item.kind {
            ItemKind::ToolResult { output, .. } => Some(output.as_str()),
            _ => None,
        })
}
iter() vs into_iter()
iter()는 빌려 순회합니다. session은 그대로입니다. 반환이 &str인 이유이기도 합니다. 출력이 아직 session 안에 있습니다.
rev()
역순. “가장 최근 도구”를 찾고 싶어서 뒤부터 봅니다.
flat_map
각 chat이 item 이터레이터를 내놓으면, 그걸 한 줄로 펼칩니다. map이면 “이터레이터의 이터레이터”가 됩니다.
find_map
앞에서부터 클로저를 적용해, 첫 Some을 반환하고 멈춥니다. ToolResult가 아니면 None이라 다음 item으로 갑니다.
match &item.kind
kind를 빌려 맞춥니다. output은 &String이 되고, .as_str()가 &str로 바꿉니다.

호출하는 쪽:

    last_tool = output.to_string();     // 빌린 조각을 내 String에 복사

도구 결과가 아직 없으면 None이고, last_tool은 이전 값을 유지합니다. “이번 대화에 도구가 없으면 직전 출력을 그대로 보여 준다”가 if let 하나로 표현됩니다.

    let model_events = match self.call_model(&session, cancel.clone(), &events).await {
        Ok(ev) => ev,
        Err(e) if is_overflow(&e) => {  // 가드: 이 조건일 때만 이 갈래
            self.store.end_chat(&chat.id, ChatStatus::Error, usage_sum).await?;
            ...
            return Err(e);
        }
        Err(e) => return Err(e),
    };
    ...
}

1..=n은 양끝을 포함하는 범위입니다. 1..n은 n을 빼니다. Err(e) if is_overflow(&e)는 match 가드입니다. overflow면 chat을 Error로 닫고, 그 외 에러는 바로 올립니다.

모델 이벤트에서 tool call만 모으기

let calls: Vec<(String, String, Value)> = new_items
    .iter()
    .filter_map(|item| match &item.kind {
        ItemKind::ToolCall { call_id, name, args } => {
            Some((call_id.clone(), name.clone(), args.clone()))
        }
        _ => None,
    })
    .collect();
if calls.is_empty() {
    self.store.end_chat(&chat.id, ChatStatus::Done, usage_sum).await?;
    ...
    return Ok(RunStatus::Done);
}

filter_map은 “없애거나(None), 꺼내거나(Some)”입니다. 텍스트 item은 버리고, tool call만 튜플로 모읍니다. clone이 세 번인 이유: item.kind는 빌려 보고 있고, 뒤 루프가 소유하는 String/Value가 필요하기 때문입니다.

타입 주석 Vec<(String, String, Value)>는 없어도 추론되지만, 세 칸이 무엇인지 읽기 쉽게 적혀 있습니다. 순서대로 call id, 도구 이름, JSON 인자입니다.

없는 도구, 거부, if let ... else

let Some(tool) = self.find_tool(&name) else {
    let result = Item::tool_result(&call_id, format!("unknown tool {name}"), true);
    self.store.append(&chat.id, result).await?;
    continue;
};

let Some(x) = ... else { ... }는 “있으면 x, 없으면 블록을 실행하고 이 스코프를 떠나라”입니다. 블록 안은 반드시 continue / return / break처럼 빠져나가야 합니다. 있으면 그 아래부터 tool을 씁니다. 

if !matches!(tool.class(), ToolClass::Read)
    && self.approver.approve(&req).await == Decision::Deny
{
    let result = Item::tool_result(&call_id, "denied", true);
    ...
    continue;
}

Read가 아니고, 승인이 Deny이면 실행하지 않습니다. matches!는 if let ToolClass::Read = tool.class() { true } else { false }와 같습니다.

tokio::select! — 둘 중 먼저 끝나는 쪽

let out: ToolOutput = tokio::select! {
    _ = cancel.cancelled() => ToolOutput {
        text: "interrupted".into(),
        is_error: true,
    },
    out = tool.call(args.clone(), &cx) => out,
};

도구가 오래 걸려도 Ctrl-C가 먼저면 왼쪽 갈래가 이깁니다. 진 쪽 작업은 취소됩니다(협조적 취소). _ = ...는 “이 갈래의 값은 안 쓴다”입니다. 오른쪽은 도구가 준 out을 그대로 식의 값이 되게 합니다.

글자가 화면에 먼저 가는 펌프

모델 HTTP가 끝나는 것을 기다리면 타자가 늦습니다. call_model은 별도의 송신 채널을 하나 더 엽니다. 

let (live_tx, mut live_rx) = mpsc::unbounded_channel();
let events_live = events.clone();       // 바깥 화면 채널의 송신 손잡이 복제
let pump = tokio::spawn(async move {
    while let Some(ev) = live_rx.recv().await {
        if let crate::types::ModelEvent::TextDelta(s) = ev {
            let _ = events_live.send(Event::TextDelta(s));
        }
    }
});
let result = self.model.stream(assembled.request, cancel.clone(), live_tx).await;
let _ = pump.await;

모델은 live_tx로 조각를 보냅니다. 펌프 작업이 ModelEvent::TextDelta만 CLI가 아는 Event::TextDelta로 바꿉니다. 두 enum이 다릅니다. 커널 안 모델 이벤트와, 화면용 이벤트입니다.

events.clone()은 채널 내용을 복사하지 않습니다. 송신자를 하나 더 만듭니다. 펌프가 가져가도 run은 원래 events로 ToolStart 등을 보냅니다.

짝이 빈 tool call 메우기

if let Some(chat) = session.chats.iter().rev().find(|c| c.id == chat_id) {
    for item in &chat.items {
        if let ItemKind::ToolCall { call_id, .. } = &item.kind {
            let has = chat.items.iter().any(|other| {
                matches!(&other.kind, ItemKind::ToolResult { call_id: id, .. } if id == call_id)
            });
            if !has {
                self.store
                    .append(chat_id, Item::tool_result(call_id, "interrupted", true))
                    .await?;
            }
        }
    }
}

find(|c| c.id == chat_id) — 조건에 맞는 첫 원소의 참조. any(|other| ...) — 하나라도 참이면 true.

안쪽 matches!의 call_id: id는 “필드는 call_id인데, 꺼낸 이름은 id로 하겠다”입니다. 바깥 루프의 call_id와 이름이 겹치지 않게 합니다. 뒤에 if id == call_id는 매크로 안의 가드입니다.

아래는 REPL 한 줄을 이해한 뒤 보기 좋습니다. 같은 문법이 반복됩니다.

파일보면 좋은 것
keel-core/src/types.rs ItemKind, Event처럼 칸을 가진 enum. Item::text의 impl Into<String> — &str과 String을 둘 다 받는 인자.
keel-core/src/traits.rs 역할만 있는 trait. AlwaysAllow / AlwaysDeny처럼 빈 구조체 + 한 줄 구현.
keel-cli/src/main.rs의 run_print REPL과 같은 채널이지만 match 대신 if let Event::TextDelta만 처리하는 짧은 버전.
keel-cli/src/config.rs의 substitute_vars &str을 잘라 가며 ${VAR}를 바꾸는 루프. 슬라이스(&rest[start + 2..]) 연습.
keel-openai/src/model.rs HTTP SSE 줄을 읽어 ModelEvent를 보내는 쪽. async와 문자열 파싱이 같이 있습니다.
막히는 줄이 있으면 타입부터 봅니다. 변수 위에 커서를 두거나, let 이름: 여기처럼 타입을 잠깐 적어 컴파일러에게 물어보면 “이게 &str인지 String인지, Option인지 Result인지”가 대부분 풀립니다. 흐름은 REPL이 돌아가는 길을 같이 보면 됩니다.
