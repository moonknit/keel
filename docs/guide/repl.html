keel REPL이 돌아가는 길

Rust를 몰라도 따라갈 수 있게, cargo run -p keel-cli로 대화 화면이 뜰 때 어떤 함수가 무엇을 하는지 코드 기준으로 풀어 쓴 안내입니다. 사용법 예시는 루트 README.md에 있습니다. 코드를 한 줄씩 읽고 싶다면 Rust 코드 읽기가 있습니다.

1. 이 코드에서 자주 나오는 Rust 말

말이 프로젝트에서의 뜻
fn함수. repl()은 “대화 화면을 돌리는 함수”입니다.
struct여러 값을 묶은 상자. Agent는 모델·도구·저장소를 한곳에 넣습니다.
enum여러 경우 중 하나. Event::TextDelta는 “글자 조각이 왔다”는 경우입니다.
async / await네트워크나 키보드처럼 기다리는 일을 멈춰 두지 않고 넘깁니다. 모델 응답을 받을 때 씁니다.
Arc<T>같은 상자를 여러 곳에서 나눠 갖는 손잡이. 저장소와 도구를 에이전트와 REPL이 같이 봅니다.
dyn Trait“이 역할을 하는 무엇이든”. dyn Model은 실제 OpenAI일 수도, 테스트용 가짜일 수도 있습니다.
mpsc한쪽으로 이벤트를 보내고 다른 쪽에서 받는 통로. 루프가 말하고, 화면이 듣습니다.

2. 실행부터 REPL까지

바이너리 이름은 keel이고 코드는 crates/keel-cli/src/main.rs 한 파일입니다. -p가 없으면 마지막에 repl()로 들어갑니다.

1. main — cwd의 .env를 읽고 run()을 부릅니다.
2. run — 플래그를 파싱하고 ~/.keel/keel.db를 엽니다.
3. session 하위 명령이면 목록/보기/삭제만 하고 끝냅니다.
4. 아니면 session을 고르고, -p면 print, 없으면 REPL.
// crates/keel-cli/src/main.rs
#[tokio::main]
async fn main() {
    let _ = dotenvy::dotenv();   // .env → 환경 변수
    if let Err(e) = run().await {
        eprintln!("{e}");
        std::process::exit(1);
    }
}

// run() 끝부분. -p 가 없으면 여기로.
if let Some(prompt) = print {
    let code = run_print(...).await?;
    std::process::exit(code);
}
repl(&db, &session.meta.id, &cwd, allow_edits).await

KEEL_HOME이 있으면 그 아래 keel.db를 씁니다. 없으면 ~/.keel입니다. 홈 폴더를 더럽히기 싫으면 README처럼 임시 디렉터리를 주면 됩니다.

3. session을 고르는 법

REPL은 “지금 이 폴더의 대화 하나”에 붙습니다. 고르는 함수는 pick_session입니다.

플래그동작
--new새 session을 DB에 만듭니다.
--resume <id>그 id를 엽니다.
없음이 cwd의 최근 session. 없으면 새로 만듭니다.
// pick_session
if cli.new { return db.create_session(cwd, model).await; }
if let Some(id) = cli.resume.clone().flatten() {
    return db.open_session(&id).await;
}
let list = db.list_sessions(Some(cwd), false).await?;
if let Some(meta) = list.into_iter().next() {
    db.open_session(&meta.id).await
} else {
    db.create_session(cwd, model).await
}
session은 저장된 대화 전체입니다. 그 안의 한 번의 질문–응답 묶음이 chat입니다. REPL에서 엔터를 칠 때마다 새 chat이 하나 생깁니다.

4. 에이전트를 조립하는 법

화면(keel-cli)은 모델을 직접 부르지 않습니다. build_agent가 Agent 상자를 만들고, 이후에는 agent.run(...)만 호출합니다. 커널은 crates/keel-core/src/agent.rs에 있습니다.

칸넣는 것역할
modelOpenAiModel 또는 ScriptedModelLLM 호출
toolsread/grep/glob/write/edit/bash + skill모델이 부르는 로컬 도구
storeSqliteStore대화 저장
approver정책 + 키보드 y/n위험한 도구를 막을지
assemblerContextAssembler다음에 모델에 넣을 창
systemAGENTS.md + 스킬 목록시스템 프롬프트
max_turns50한 chat에서 모델 호출 한도
// build_agent — REPL은 print=false, 그래서 키보드 승인을 붙입니다.
let skills = discover(cwd);
let mut tools = default_tools();         // 기본 로컬 도구 6개
tools.push(Arc::new(SkillTool { skills: skills.clone() }));
let system = format!("{}\n{}", load_agents_md(cwd), catalog_text(&skills));
let model = if KEEL_SCRIPTED=1 { ScriptedModel } else { OpenAiModel::from_env() };
let approver = PolicyApprover { policy, inner: StdinApprover };

일반 실행은 항상 OpenAiModel입니다. KEEL_SCRIPTED=1일 때만 “ok”만 말하는 가짜 모델입니다. 테스트용입니다.

5. 입력 한 줄이 처리되는 법

repl()은 무한 루프입니다. rustyline이 > 프롬프트를 그리고, 한 줄을 받으면 아래 순서로 봅니다.

빈 줄 → 무시
슬래시 명령(/help 등) → 로컬에서 처리하고 모델에 안 보냄
그 외 → 사용자 메시지로 agent.run
// crates/keel-cli/src/main.rs  repl()
loop {
    let line = rl.readline("> ")?;
    let line = line.trim();
    if line.is_empty() { continue; }
    if line == "/exit" { break; }
    // /help /last /skills /name /session /compact /skill: 처리
    let prompt = if line.starts_with("/skill:") { 스킬 본문 } else { line };
    // 여기서부터 한 chat
    agent.run(session_id, prompt, cwd, cancel, tx).await?;
}
store.close(session_id).await?;

한 줄을 모델에 넘기기 직전에 세 가지를 같이 켭니다.

  1. 이벤트 통로 tx / rx — 루프가 보내는 소식을 화면이 받습니다.
  2. 취소 토큰 — 다른 작업이 Ctrl-C를 기다리다가 토큰을 꺾습니다.
  3. 프린터 작업 — rx를 듣는 동안 글자와 도구 줄을 바로 찍습니다.

agent.run이 끝나면 프린터도 끝나고, 직전 도구 요약이 last_tool에 남습니다. 루프를 빠져나오면 store.close가 session 잠금(lock_pid)을 풉니다.

6. 슬래시 명령

/help가 적어 주는 목록과, 실제로 repl()이 처리하는 목록이 조금 다릅니다.

입력코드가 하는 일
/exit루프를 빠져나오고 session을 닫습니다. Ctrl-D도 rustyline이 에러로 받아 같은 효과입니다.
/help명령 이름을 한 줄로 출력합니다.
/last직전 도구의 이름, 성공 여부, 시간, 줄 수를 출력합니다. 도구 출력 전체는 아닙니다.
/skillscwd에서 SKILL.md를 다시 찾아 이름과 설명만 찍습니다.
/name 제목지금 session 제목을 DB에 바꿉니다.
/sessionid, cwd, 모델 이름을 출력합니다.
/compactv2 예정만 출력합니다. 요약을 하지 않습니다.
/skill:이름그 스킬 본문과 skill_root=를 사용자 메시지처럼 모델에 넣습니다. 슬래시만으로 끝나지 않습니다.
그 외 일반 문장그대로 user 텍스트가 됩니다.
/help에는 /new와 /resume이 적혀 있지만, repl() 루프에는 해당 분기가 없습니다. 새 session이나 이어하기는 프로세스를 다시 켤 때 --new / --resume으로 합니다.

7. 한 번의 대화가 모델·도구를 도는 법

엔터를 친 뒤의 본체는 Agent::run입니다. “질문 하나 = chat 하나 = 최대 50턴”입니다. 한 턴은 모델 호출 한 번입니다.

session을 열고 새 chat을 만듭니다. user 문장을 DB에 붙입니다.
오래된 chat이 너무 길면 통째로 빼고 Notice만 잠깐 넣습니다. 저장하지는 않습니다.
모델에 system + 최근 대화 + 도구 목록을 보냅니다. 글자 조각은 바로 Event로 나옵니다.
모델이 텍스트만 내면 chat을 끝내고 돌아옵니다.
모델이 tool call을 내면 하나씩 승인 → 실행 → 결과를 DB에 붙인 뒤 다음 턴으로 갑니다.
// crates/keel-core/src/agent.rs  핵심만
let chat = self.store.begin_chat(session_id, Some(title)).await?;
self.store.append(&chat.id, user_item).await?;

for turn in 1..=self.max_turns {
    let assembled = self.assembler.assemble(&session, system, tool_specs);
    let model_events = self.model.stream(assembled.request, cancel, live_tx).await?;

    let calls = model_events 중에서 ToolCall 만;
    if calls.is_empty() {
        end_chat(Done);
        return Done;
    }
    for call in calls {
        승인 확인;
        tool.call(args, cwd);
        store.append(tool_result);
    }
}

끝나는 경우 네 가지입니다.

상태언제
Done모델이 도구 없이 텍스트만 냄
InterruptedCtrl-C로 취소 토큰이 꺾임
Limit50턴을 다 씀
Error지금은 루프가 잘 안 씁니다. CLI print 모드는 이 코드를 1로 매깁니다.

도구는 한 턴 안에서 직렬입니다. 여러 개를 한 번에 받아도 앞에서부터 하나씩 실행합니다. 결과가 없는 tool call을 모델에 다시 보내지 않습니다. 취소되면 interrupted 결과를 합성해 짝을 맞춥니다.

8. 글자가 바로 찍히는 법

세 층이 이어져야 타자가 나오듯 보입니다.

  1. OpenAiModel::stream이 HTTP 본문을 끝까지 모으지 않고 SSE data: 줄을 조각으로 파싱합니다. response.output_text.delta가 오는 즉시 ModelEvent::TextDelta를 보냅니다.
  2. Agent::run이 그 델타를 Event::TextDelta로 바꿉니다.
  3. REPL 프린터가 받아서 print!하고 flush합니다. 도구가 시작되면 ▸ 이름 인자, 끝나면 ✓/✗를 한 줄로 찍습니다. 
// REPL 프린터
Event::TextDelta(s) => { print!("{s}"); stdout.flush(); }
Event::ToolStart { name, args } => println!("\\n▸ {name}  {args}");
Event::ToolEnd { ok, .. } => println!("  {}", if ok { "✓" } else { "✗" });
Event::RunEnd { .. } => println!();

print 모드(-p)는 같은 루프를 쓰지만 프린터는 TextDelta만 보여 줍니다. 도구 줄과 승인 UI는 없습니다.

9. 승인 게이트

도구를 실행하기 전에 PolicyApprover가 먼저 보고, 정책이 “모르겠다”고 하면 REPL의 StdinApprover가 키보드를 묻습니다. 

  allow bash {"command":"curl https://..."}? [y]es [a]lways [n]o
종류REPL 기본
Read (read grep glob skill)묻지 않고 실행
Write (write edit)묻습니다. --allow-edits면 자동 허용
안전한 bash + OS jailSeatbelt/bwrap이 있으면 자동 허용
위험한 bash (rm -rf, curl, git push …)항상 다시 묻습니다
a / always그 도구 이름을 프로세스 메모리 allowlist에 넣습니다. 디스크에는 안 남습니다

정책 코드는 crates/keel-tools/src/policy.rs입니다. Read가 아닌데 Deny이면 도구를 실행하지 않고 observation에 denied를 넣습니다.

10. 도구 목록

모델이 볼 수 있는 로컬 도구는 default_tools()와 skill입니다. 작업 디렉터리는 session cwd입니다.

이름하는 일클래스
read파일 읽기. offset/limit으로 줄 단위Read
grep정규식으로 내용 검색Read
glob경로 패턴으로 파일 찾기Read
writecwd 아래 파일 쓰기. 없는 폴더도 만듦Write
editold가 정확히 한 번일 때만 바꿈Write
bash새 셸 한 번. jail이 있으면 네트워크·바깥 쓰기 차단Exec
skillSKILL.md 본문과 루트 경로를 돌려줌Read

web_search는 로컬 도구가 아닙니다. OpenAI 요청에 hosted 도구로 붙고, 검색은 서버가 합니다. 결과는 HostedTool item으로 transcript에 남습니다.

스킬 파일은 .agents/skills/이름/SKILL.md를 cwd에서 조상으로 올라가며 찾고, 그다음 ~/.agents/skills, Claude 경로도 봅니다. 기동 때는 이름과 설명만 시스템 프롬프트에 넣습니다(대략 4,000자). 본문은 /skill:이름이거나 모델이 skill 도구를 부를 때 붙습니다.

11. 아직 REPL에 없는 것

  • /new, /resume — help에만 있고 루프에 분기가 없습니다.
  • MCP 서버 — keel-mcp crate는 있으나 CLI가 기동 시 연결하지 않습니다.
  • 마크다운 렌더, 전체 화면 TUI.
  • 대화 중 끼어들기(Steer), 요약 compaction.
  • 도구 출력 전문을 /last로 다시 보기. 지금은 한 줄 요약만입니다.
기준 코드: crates/keel-cli/src/main.rs, crates/keel-core/src/agent.rs, crates/keel-tools/src/policy.rs, crates/keel-skills/src/lib.rs. 구현이 바뀌면 이 안내도 같이 고칩니다.
